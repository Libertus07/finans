## 2024-08-30 - Caching Intl instances and RangeError Edge Case
**Learning:** Instantiating `Intl.NumberFormat` and `Intl.DateTimeFormat` on every function call in React render cycles causes significant performance overhead (measured ~60x slowdown compared to caching). When optimizing `new Date().toLocaleDateString()` to use a cached `Intl.DateTimeFormat`, it's critical to realize that `Intl.DateTimeFormat().format(new Date('invalid'))` throws a `RangeError: Invalid time value`, whereas `toLocaleDateString` gracefully handles invalid dates by returning 'Invalid Date'.
**Action:** Always instantiate `Intl` formatters once at the module level and reuse them. When migrating to `Intl.DateTimeFormat`, always add an explicit `isNaN(date)` check to prevent unexpected crashes in production.
