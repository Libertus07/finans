## 2024-05-18 - Caching Intl Formatters
**Learning:** `Intl.NumberFormat` and `Intl.DateTimeFormat` constructors are surprisingly slow. When used inside functions like `formatCurrency` that are called inside render loops for long lists (e.g., Transactions page), they cause measurable performance overhead during re-renders. Also, `Intl.DateTimeFormat` doesn't handle invalid dates as gracefully as `.toLocaleDateString()` and requires explicit `isNaN(date)` checks to prevent throwing `RangeError` on invalid inputs.
**Action:** Always instantiate `Intl` formatters once at the module level (caching them) instead of inside helper functions or component bodies to prevent GC churn and block the main thread. Always handle invalid dates explicitly when switching to `Intl.DateTimeFormat`.
