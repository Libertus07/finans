## 2024-05-18 - [Intl.NumberFormat & Intl.DateTimeFormat caching]
**Learning:** Repeatedly instantiating `Intl.NumberFormat` inside formatting helpers (like `formatCurrency`) causes significant overhead during frequent renders or loops. When refactoring `new Date(...).toLocaleDateString()` to use a cached `Intl.DateTimeFormat` instance for performance, note that `Intl.DateTimeFormat().format(new Date('invalid'))` throws a `RangeError: Invalid time value`, whereas `toLocaleDateString` gracefully handles it. Always add a date validity check (e.g., `isNaN(date)`) when implementing this optimization.
**Action:** Always instantiate `Intl` formatters once at the module level and reuse them for significant performance gains, ensuring we handle `Invalid Date` gracefully when substituting `toLocaleDateString`.
