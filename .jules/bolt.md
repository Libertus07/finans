## 2024-06-19 - Cache Intl instances
**Learning:** Recreating `Intl.NumberFormat` and `Intl.DateTimeFormat` on every function call (e.g., inside `formatCurrency` and `formatDate`) is computationally expensive and causes significant overhead during large list renders. However, directly swapping to `Intl.DateTimeFormat().format(new Date(dateStr))` is dangerous because it throws a `RangeError: Invalid time value` for invalid dates, unlike `toLocaleDateString` which safely returns "Invalid Date".
**Action:** When optimizing date formatting with cached `Intl` instances, always explicitly check for invalid dates (`isNaN(date)`) to prevent runtime exceptions and preserve fallback behavior.
## 2024-06-19 - Fix Netlify CI Failure for Subdirectory SPA
**Learning:** A 'Deploy failed' status on Netlify CI checks (especially for "Pages changed", "Header rules", or "Redirect rules") in this specific setup usually results from the app being served from a subdirectory (`patron-finans`) with a `base: './'` Vite configuration that conflicts with Netlify's default assumptions for SPA routing.
**Action:** When asked to fix this specific Netlify CI deployment failure, do NOT modify `package.json` or `vite.config.js`. Instead, create a `netlify.toml` file at the repository root containing explicit `[build]` overrides (e.g., `base = "patron-finans"`, `publish = "dist"`) and add a `_redirects` file (`/* /index.html 200`) inside the public directory to ensure the SPA handles routing correctly.
