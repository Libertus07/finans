## 2024-10-30 - Optimize Intl.NumberFormat and Intl.DateTimeFormat Instantiation
**Learning:** Instantiating `Intl.NumberFormat` and `Intl.DateTimeFormat` on every function call (e.g., inside `formatCurrency` and `formatDate`) is extremely slow. Since these functions are used everywhere in the application (lists, tables, dashboards), creating new instances every time causes severe performance overhead. Extracting them to module-level constants reduces execution time by over 98% (e.g., 5.7s to 78ms for 100,000 calls).
**Action:** Extract formatters as module-level constants to reuse them across function calls. When optimizing `new Date(...).toLocaleDateString()`, handle `Invalid Date` gracefully by adding an `isNaN(date)` check, as `Intl.DateTimeFormat().format()` throws a `RangeError` on invalid dates.
