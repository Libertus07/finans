## 2024-05-18 - Intl Object Caching Optimization
**Learning:** `Intl.NumberFormat` and `Intl.DateTimeFormat` instantiations are known to be computationally expensive in JavaScript. In this architecture, where `App.jsx` handles state and passes it down, child components can be forced to re-render frequently. Recreating these `Intl` objects on every single render (especially in heavily used formatting functions like `formatCurrency` and `formatDate`) creates noticeable overhead and impacts performance.
**Action:** When migrating native string formatting methods like `new Date().toLocaleDateString()` to a cached `Intl.DateTimeFormat.format()` instance, explicitly handle invalid dates (e.g., checking `isNaN(date)`) to preserve fallback strings like 'Invalid Date' and avoid breaking exceptions. Always instantiate `Intl` formatters at the module level (cached) and reuse them to prevent performance overhead during frequent re-renders.
