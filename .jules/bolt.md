## 2025-02-18 - Caching Intl formatters to prevent continuous instantiation in list rendering
**Learning:** In a codebase that heavily features list views (e.g. Products, Tables, ZReports, Investments) and formats currency on a per-item or per-row basis using `Intl.NumberFormat`, continually instantiating `new Intl.NumberFormat()` inside the helper functions causes significant and avoidable CPU overhead on every render cycle. `Intl` instantiation is a notoriously slow synchronous operation.
**Action:** Extract `Intl.NumberFormat` and `Intl.DateTimeFormat` into module-level constants where the app's default locale ('tr-TR') is configured. Also ensure edge cases with invalid dates are handled in `formatDate` gracefully now that `DateTimeFormat` is used directly since `format()` throws on an invalid date.
