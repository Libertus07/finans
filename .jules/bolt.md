## 2026-11-01 - Intl Formatter Caching
**Learning:** Repeatedly instantiating `Intl.NumberFormat` and calling `toLocaleDateString()` inside formatting functions is a significant performance bottleneck in React apps when those functions are called repeatedly in lists or charts. Additionally, when switching to a cached `Intl.DateTimeFormat` instance, `Intl.DateTimeFormat().format(new Date('invalid'))` throws a `RangeError: Invalid time value`, whereas `toLocaleDateString` gracefully returned 'Invalid Date'.
**Action:** Always extract and cache these formatters as module-level constants. When refactoring `new Date(...).toLocaleDateString()` to use a cached `Intl.DateTimeFormat` instance, always add a date validity check (e.g., `isNaN(date)`) and explicitly handle invalid dates by returning 'Invalid Date' to preserve exact functionality.
