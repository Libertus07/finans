## 2024-05-18 - [Optimizing Intl formatters]
**Learning:** Repeatedly instantiating Intl.NumberFormat and Intl.DateTimeFormat inside formatting helpers (like formatCurrency) causes significant overhead during frequent renders or loops. Always instantiate the formatter once at the module level and reuse it for a ~100x performance gain in execution time. When refactoring new Date().toLocaleDateString() to use a cached Intl.DateTimeFormat instance, remember that Intl.DateTimeFormat().format(new Date('invalid')) throws a RangeError: Invalid time value, whereas toLocaleDateString gracefully returns 'Invalid Date'. Always add a date validity check (e.g., isNaN(date)) when implementing this optimization.
**Action:** Extract Intl formatters into module-level constants and add a validity check for dates.
